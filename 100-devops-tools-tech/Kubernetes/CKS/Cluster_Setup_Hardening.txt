Lab - Run CIS Benchmark Assessment tool on Ubuntu
---------------------------------------------------
CIS-CAT tool test
--------------------

Download the CIS benchmark PDF’s from the below link:

https://www.cisecurity.org/cis-benchmarks/#kubernetes

Go to the `Server Software` section and click on the `Virtualization`. 

There you will see multiple items that fall into the virtualization category such as VMware, docker and kubernetes. Now, move on to the Kubernetes and expand it to see more options then download CIS Kubernetes Benchmark version 1.6.0.

Download the CIS CAT tool’ from the below link: 

https://www.cisecurity.org/cybersecurity-tools/cis-cat-pro/cis-benchmarks-supported-by-cis-cat-pro/

Download the CIS CAT Lite tool from the below link:

https://learn.cisecurity.org/cis-cat-lite

==============================
## LAB #### LAB #### LAB #####
==============================


Download the kube-bench_0.12.0_linux_amd64.deb binary:

# curl -L https://github.com/aquasecurity/kube-bench/releases/download/v0.12.0/kube-bench_0.12.0_linux_amd64.deb -o kube-bench_0.12.0_linux_amd64.deb

Then install it using dpkg:

# sudo dpkg -i kube-bench_0.12.0_linux_amd64.deb

To verify, run the following and you should expect to see 0.12.0 as an output:

# kube-bench version

Run a kube-bench test for all targets and observe the results.

# kube-bench run

Fix the warning on test 1.3.1 Ensure that the --terminated-pod-gc-threshold argument is set as appropriate. Follow the exact remediation steps given in the Remediation section of the given test.

To run a specific test using kube-bench, you can use the --check parameter. For example, to check for the test 1.3.1, you can run the following command:

---

# kube-bench --check="1.3.1"
# vi  /etc/kubernetes/manifests/kube-controller-manager.yaml
- --terminated-pod-gc-threshold=10

---

Fix this failed test 1.1.12 Ensure that the etcd data directory ownership is set to etcd:etcd. Follow the exact remediation steps given in the Remediation section of the given test.

Tip: Run the following command to check for this test:

---
# kube-bench --check="1.1.12"

# ps -ef | grep etcd
# chown etcd:etcd /var/lib/etcd
---

Fix this failed test 1.4.1: Ensure that the --profiling argument is set to false. Follow the exact remediation steps given in the Remediation section of the given test.

Tip: Run the following command to check for this test:

---
# kube-bench --check="1.4.1"

# vi /etc/kubernetes/manifests/kube-scheduler.yaml
- --profiling=false

---

for revalidation:

# kube-bench run --targets="master"
