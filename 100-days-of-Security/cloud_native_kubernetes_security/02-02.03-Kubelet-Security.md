# 02.03 - Kubelet Security

## 1️⃣ What This Topic Is

Kubelet Security examines security measures for securing Kubernetes Kubelet component, understanding authentication, authorization, and security configurations.

**What this means:**
- Kubelet = Kubernetes agent on worker nodes
- Manages pods and containers on node
- Communicates with API server
- Critical for worker node security

**The Key Concepts:**

1. **Kubelet Components**
   - Authentication (who can access Kubelet)
   - Authorization (what can be done)
   - API server communication
   - Resource management (CPU, memory)
   - Pod and container management

2. **Security Areas**
   - Kubelet authentication (client certs, tokens)
   - Kubelet authorization (webhooks)
   - Read-only file systems
   - Resource quotas (CPU, memory limits)
   - Security contexts (seccomp, AppArmor)

**Why this matters:**
- Kubelet runs as root on worker node
- Kubelet manages all pods and containers
- Kubelet compromise = worker node compromise
- Kubelet is primary attack target on worker nodes

---

## 2️⃣ What Problem It Solves

### Problem 1: Unauthenticated Kubelet Access

**Without Kubelet security:**
- Anyone can access Kubelet API (port 10250)
- Attacker can list pods and containers
- Attacker can execute commands in pods
- Worker node compromise

**With Kubelet security:**
- Authentication required for Kubelet access
- Only authorized users can access
- Unauthorized access prevented
- Worker node protected

### Problem 2: Over-Privileged Kubelet

**Without Kubelet security:**
- Kubelet runs with maximum privileges
- Attacker can escape to host
- Attacker can execute commands on worker node
- Cluster-wide compromise

**With Kubelet security:**
- Least privilege Kubelet configuration
- Resource quotas enforced
- Security contexts enforced
- Privilege escalation prevented

### Problem 3: No Resource Limits

**Without Kubelet security:**
- Pods can consume unlimited resources
- No CPU or memory limits
- DoS attacks possible (resource exhaustion)
- Worker node disruption

**With Kubelet security:**
- Resource quotas enforced
- CPU and memory limits set
- DoS attacks prevented
- Worker node stability maintained

### Real-World Impact

**Example: Tesla Kubernetes Breach (2018)**
- **Vulnerability**: Unauthenticated Kubelet API
- **Root cause**: No Kubelet authentication
- **Kubelet issue**: Attacker accessed Kubelet without authentication
- **Impact**: Attacker deployed miners across cluster
- **Lesson**: Configure Kubelet authentication

**Example: Uber Data Breach (2016)**
- **Vulnerability**: Over-privileged Kubelet
- **Root cause**: No Kubelet least privilege
- **Kubelet issue**: Attacker escaped container to host
- **Impact**: 57 million customer records accessed
- **Lesson**: Configure Kubelet least privilege

**Example: Capital One Breach (2019)**
- **Vulnerability**: No resource limits
- **Root cause**: No CPU/memory quotas
- **Kubelet issue**: Resource exhaustion DoS
- **Impact**: Service disruption, data access
- **Lesson**: Configure resource quotas

## 4️⃣ How It Works (Conceptual)

### Kubelet Security Areas

**1. Authentication**
- **Purpose**: Verify who can access Kubelet
- **Security Measures**: 
  - Client certificate authentication
  - Token authentication
  - OIDC authentication
  - Anonymous access (disabled)
- **Common Misconfigurations**: 
  - No authentication
  - Weak authentication (weak certificates)
  - Anonymous access enabled
  - Long-lived tokens
- **Example**: Kubelet with client certificate authentication

**Authentication Methods:**
- **Client Certificates**: 
  - X.509 certificates
  - Mutual TLS (mTLS)
  - Certificate rotation
  - Revocation

- **Tokens**: 
  - Bearer tokens
  - Service account tokens
  - Token rotation
  - TTL (time-to-live)

**Example**:
```yaml
# Kubelet with client certificate authentication (secure)
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
authentication:
  anonymous:
    enabled: false
  clientCAFile: /var/lib/kubelet/pki/ca.crt
  x509:
    clientCAFile: /var/lib/kubelet/pki/ca.crt
    certFile: /var/lib/kubelet/pki/kubelet.crt
    keyFile: /var/lib/kubelet/pki/kubelet.key
```

**2. Authorization (Webhook)**
- **Purpose**: Control what can be done with Kubelet
- **Security Measures**: 
  - Authorization webhook
  - Namespace authorization
  - Resource quotas
  - Pod security policies
- **Common Misconfigurations**: 
  - No authorization (all access allowed)
  - Over-privileged authorization
  - No resource quotas
  - No PSPs
- **Example**: Kubelet with authorization webhook

**Authorization Concepts:**
- **Webhook Authorization**: 
  - External webhook validates requests
  - Rejects or allows requests
  - Flexible authorization

- **Namespace Authorization**: 
  - Restricts access to pods by namespace
  - Tenant-level isolation
  - Least privilege

**Best Practices:**
- Use least privilege authorization
- Use authorization webhook for flexibility
- Use namespace authorization for multi-tenancy
- Implement resource quotas
- Implement PSPs

**Example**:
```yaml
# Kubelet with authorization webhook (secure)
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
authorization:
  mode: Webhook
  webhook:
    cacheAuthorizedTTL: 5m
    configFile: /var/lib/kubelet/authorization-webhook.yaml
    timeout: 10s
```

**3. Read-Only File Systems**
- **Purpose**: Prevent container file system modifications
- **Security Measures**: 
  - Read-only root file system
  - Read-only container file systems
  - Security contexts (readOnlyRootFilesystem)
- **Common Misconfigurations**: 
  - Writable root file system
  - Writable container file systems
  - Attackers can modify files
  - Malware installation
- **Example**: Kubelet with read-only file system

**Read-Only Best Practices:**
- Use read-only root file system
- Use read-only container file systems
- Use security contexts (readOnlyRootFilesystem)
- Prevent attacker from modifying files
- Prevent malware installation

**Example**:
```yaml
# Pod with read-only file system (secure)
apiVersion: v1
kind: Pod
metadata:
  name: read-only-pod
spec:
  containers:
  - name: app
    image: nginx:1.25-alpine
    securityContext:
      readOnlyRootFilesystem: true
```

**4. Resource Quotas**
- **Purpose**: Prevent resource exhaustion and DoS attacks
- **Security Measures**: 
  - CPU limits (requests and limits)
  - Memory limits (requests and limits)
  - Resource quotas (namespace-level)
  - Pod limits (node-level)
- **Common Misconfigurations**: 
  - No CPU or memory limits
  - No resource quotas
  - Resource exhaustion DoS attacks
  - Worker node disruption
- **Example**: Kubelet with resource quotas

**Resource Quota Best Practices:**
- Implement CPU and memory requests/limits
- Implement namespace resource quotas
- Implement pod limits
- Implement node resource limits
- Monitor resource usage

**Example**:
```yaml
# Namespace with resource quota (secure)
apiVersion: v1
kind: ResourceQuota
metadata:
  name: compute-quota
  namespace: production
spec:
  hard:
    requests.cpu: "4"
    requests.memory: 8Gi
    limits.cpu: "8"
    limits.memory: 16Gi
```

**5. Security Contexts**
- **Purpose**: Restrict container capabilities and system calls
- **Security Measures**: 
  - Seccomp profiles
  - AppArmor profiles
  - Drop capabilities
  - No root user
  - No privilege escalation
- **Common Misconfigurations**: 
  - No security contexts
  - Root user in containers
  - Excessive capabilities
  - Container escape possible
  - Privilege escalation possible
- **Example**: Pod with security contexts

**Security Context Best Practices:**
- Run as non-root user
- Drop all capabilities
- Use seccomp profiles
- Use AppArmor profiles
- Prevent privilege escalation
- Use read-only file system

**Example**:
```yaml
# Pod with security contexts (secure)
apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 1000
    fsGroup: 1000
    seccompProfile:
      type: RuntimeDefault
  containers:
  - name: app
    image: nginx:1.25-alpine
    securityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop: [ALL]
      readOnlyRootFilesystem: true
```

```bash
echo "=== Pod Security Policy Implementation ==="

  name: restricted

  privileged: false
  allowPrivilegeEscalation: false

  - ALL
  volumes:
  - configMap
  - downwardAPI
  - emptyDir
  - persistentVolumeClaim
  - secret

  hostIPC: false
  hostPID: false
```
