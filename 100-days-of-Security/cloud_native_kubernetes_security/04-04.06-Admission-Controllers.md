# 04.06 - Admission Controllers

## 1️⃣ What This Topic Is

Admission Controllers examines security measures for securing Kubernetes admission controllers, understanding validating admission controllers, mutating admission controllers, and secure admission controller configurations.

**What this means:**
- Kubernetes admission = controlling requests to Kubernetes API
- Validating admission controllers = validating requests before persistence
- Mutating admission controllers = modifying requests before persistence
- Secure admission controller configurations (least privilege, defense in depth)

**The Key Concepts:**

1. **Kubernetes Admission Controller Mechanisms**
   - Validating admission controllers
   - Mutating admission controllers
   - Admission control logic (validation, mutation, rejection)
   - Admission controller security (RBAC, ABAC)
   - Admission controller monitoring (admission events, admission failures)

2. **Security Principles**
   - Defense in depth (validation, mutation, RBAC, monitoring)
   - Least privilege (admission controller permissions)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (audit logging)

**Why this matters:**
- Admission controllers are critical for cluster security
- Admission controllers control all requests to Kubernetes API
- Admission controller compromise = cluster-wide compromise
- Admission controllers handle all admission decisions

## 2️⃣ What Problem It Solves

### Problem 1: Unmanaged Admission Controllers

**Without admission controller security:**
- Unmanaged admission controllers
- Attacker can bypass validation
- Cluster compromise
- Data theft and service disruption

**With admission controller security:**
- Managed admission controllers
- Attacker cannot bypass validation
- Cluster protected
- Data and services protected

### Problem 2: Over-Privileged Admission Controllers

**Without admission controller security:**
- Over-privileged admission controllers
- Attacker can escalate privileges
- Cluster compromise
- Data theft and service disruption

**With admission controller security:**
- Least privilege admission controllers
- Privilege escalation prevented
- Cluster protected
- Data and services protected

### Problem 3: No Admission Controller Monitoring

**Without admission controller security:**
- No admission controller monitoring
- Admission events undetected
- Admission incidents undetected
- Incident response delayed
- Cluster compromise

**With admission controller security:**
- Admission controller monitoring enabled
- Admission events detected
- Admission incidents detected
- Real-time detection
- Rapid incident response
- Cluster protected

### Real-World Impact

**Example: Tesla Kubernetes Breach (2018)**
- **Vulnerability**: Over-privileged admission controllers
- **Root cause**: No admission controller least privilege
- **Admission controller issue**: Attacker bypassed validation
- **Impact**: Attacker deployed miners across cluster
- **Lesson**: Implement admission controller least privilege

**Example: Uber Data Breach (2016)**
- **Vulnerability**: No admission controller validation
- **Root cause**: No admission controller validation logic
- **Admission controller issue**: Attacker bypassed admission validation
- **Impact**: 57 million customer records accessed
- **Lesson**: Implement admission controller validation

**Example: Capital One Breach (2019)**
- **Vulnerability**: No admission controller monitoring
- **Root cause**: No admission controller audit logging
- **Admission controller issue**: Admission events undetected
- **Impact**: 106 million customer records accessed
- **Lesson**: Implement admission controller monitoring

## 4️⃣ How It Works (Conceptual)

### Kubernetes Admission Controller Mechanisms

**1. Validating Admission Controllers**
- **Purpose**: Validate requests to Kubernetes API
- **Security Measures**: 
  - Request validation (API validation, resource validation)
  - Security validation (RBAC, ABAC)
  - Compliance validation (security policies)
  - Request rejection
- **Common Misconfigurations**: 
  - No validation logic (all requests accepted)
  - Over-permissive validation logic (allow all)
  - No security validation (no RBAC, no ABAC)
  - No compliance validation (no security policies)
  - No request rejection (all requests accepted)
- **Example**: Validating admission controllers with validation logic

**Validating Admission Controller Types:**
- **Request Validation**: 
  - API validation (API version, API resource)
  - Resource validation (resource name, resource namespace)
  - Security validation (RBAC, ABAC)
  - Compliance validation (security policies)
  - Request rejection

- **Security Validation**: 
  - RBAC validation (user permissions)
  - ABAC validation (attributes, policies)
  - Security policy validation
  - Security validation enforcement

- **Compliance Validation**: 
  - Security policy validation
  - Compliance validation (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Security policy enforcement
  - Compliance reporting

- **Request Rejection**: 
  - Request rejection logic
  - Request rejection enforcement
  - Request rejection monitoring
  - Request rejection logging

**Best Practices:**
- Implement request validation
- Implement security validation
- Implement compliance validation
- Implement request rejection
- Regular admission controller audits

**Example**:
```yaml
# Validating admission controllers with validation logic (secure, advanced)
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingWebhookConfiguration
metadata:
  name: validating-webhook
webhooks:
- name: security-validation-webhook
  rules:
  - operations: ["CREATE", "UPDATE", "DELETE"]
    apiGroups: ["*"]
    apiVersions: ["*"]
    resources: ["pods", "deployments", "services", "configmaps", "secrets"]
    scope: "*"
  - operations: ["GET", "LIST", "WATCH"]
    apiGroups: ["*"]
    apiVersions: ["*"]
    resources: ["secrets", "configmaps"]
    scope: "*"
  failurePolicy: Fail
  matchPolicy: Equivalent
  timeoutSeconds: 30
  admissionReviewVersions: ["v1"]
  sideEffects: NoneOnDryRun
  clientConfig:
    service:
      name: validating-webhook-service
      namespace: admission-system
      path: /validate
```

**2. Mutating Admission Controllers**
- **Purpose**: Mutate requests to Kubernetes API
- **Security Measures**: 
  - Request mutation (API mutation, resource mutation)
  - Security mutation (RBAC, ABAC)
  - Compliance mutation (security policies)
  - Request modification
- **Common Misconfigurations**: 
  - No mutation logic (all requests accepted)
  - Over-permissive mutation logic (allow all mutations)
  - No security mutation (no RBAC, no ABAC)
  - No compliance mutation (no security policies)
  - No request modification (all requests accepted)
- **Example**: Mutating admission controllers with mutation logic

**Mutating Admission Controller Types:**
- **Request Mutation**: 
  - API mutation (API version, API resource)
  - Resource mutation (resource name, resource namespace)
  - Security mutation (RBAC, ABAC)
  - Compliance mutation (security policies)
  - Request modification

- **Security Mutation**: 
  - RBAC mutation (user permissions)
  - ABAC mutation (attributes, policies)
  - Security policy mutation
  - Security validation enforcement

- **Compliance Mutation**: 
  - Security policy mutation
  - Compliance validation (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Security policy enforcement
  - Compliance reporting

- **Request Modification**: 
  - Request modification logic
  - Request modification enforcement
  - Request modification monitoring
  - Request modification logging

**Best Practices:**
- Implement request mutation
- Implement security mutation
- Implement compliance mutation
- Implement request modification
- Regular admission controller audits

**Example**:
```yaml
# Mutating admission controllers with mutation logic (secure, advanced)

      namespace: admission-system
      path: /mutate
```

**3. Admission Controller Security**
- **Purpose**: Provide security for admission controllers
- **Security Measures**: 
  - Admission controller RBAC (roles, role bindings)
  - Admission controller ABAC (attributes, policies)
  - Admission controller validation (security validation)
  - Admission controller mutation (security mutation)
- **Common Misconfigurations**: 
  - No admission controller RBAC (all admission controllers have cluster-admin)
  - No admission controller ABAC (all admission controllers have cluster-admin)
  - No admission controller validation (no security validation)
  - No admission controller mutation (no security mutation)
- **Example**: Admission controllers with RBAC

**Admission Controller Security Types:**
- **Admission Controller RBAC**: 
  - Roles (namespace-level, cluster-level)
  - Role bindings (associate roles with subjects)
  - Cluster roles (cluster-level)
  - Cluster role bindings (associate cluster roles with subjects)
  - Least privilege

- **Admission Controller ABAC**: 
  - ABAC policies (attributes, rules)
  - ABAC mode (admission mode)
  - ABAC file configuration
  - ABAC monitoring
  - Least privilege

- **Admission Controller Validation**: 
  - Security validation (RBAC, ABAC)
  - Security policy validation
  - Security validation enforcement
  - Security validation monitoring

- **Admission Controller Mutation**: 
  - Security mutation (RBAC, ABAC)
  - Security policy mutation
  - Security validation enforcement
  - Security mutation monitoring

**Best Practices:**
- Implement admission controller RBAC (least privilege)
- Implement admission controller ABAC (least privilege)
- Implement admission controller validation
- Implement admission controller mutation
- Regular admission controller audits

**Example**:
```yaml
# Admission controllers with RBAC (secure, advanced)
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: admission-controller-role
rules:
- apiGroups: ["admissionregistration.k8s.io"]
  resources: ["validatingwebhookconfigurations", "mutatingwebhookconfigurations"]
  verbs: ["get", "list", "watch", "create", "update", "delete"]
- apiGroups: [""]
  resources: ["configmaps", "secrets"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: admission-controller-role-binding
subjects:
- kind: User
  name: "admission-controller@example.com"
roleRef:
  kind: ClusterRole
  name: admission-controller-role
  apiGroup: rbac.authorization.k8s.io
```
