# 04.11 - Pod Security Policies (Admission context)

## 1️⃣ What This Topic Is

Pod Security Policies (Admission context) examines security measures for securing Kubernetes pod security policies, understanding pod security standards, admission control, and secure pod security policy configurations.

**What this means:**
- Kubernetes Pod Security Policies = pod security standards (Pod Security Standards)
- Pod Security Standards = security profiles (baseline, restricted, privileged)
- Admission control = enforcing pod security standards (Pod Security Policies)
- Secure pod security policy configurations (namespaces, labels, pods)

**The Key Concepts:**

1. **Kubernetes Pod Security Policy Security Areas**
   - Pod Security Standards (baseline, restricted, privileged)
   - Pod Security Policies (Pod Security Policies)
   - Admission control (validating, mutating)
   - Pod Security Policy enforcement (CNI plugins, kubelet)
   - Pod Security Policy monitoring (pod admission events, policy violations)

2. **Security Principles**
   - Defense in depth (Pod Security Standards, admission control, enforcement, monitoring)
   - Least privilege (pod security policy access)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (audit logging)

**Why this matters:**
- Pod Security Policies are critical for cluster security
- Pod Security Policies control all pod security
- Pod Security Policies compromise = cluster-wide compromise
- Pod Security Policies handle all pod security

## 2️⃣ What Problem It Solves

### Problem 1: Unmanaged Pod Security

**Without pod security policies:**
- Unmanaged pod security (all pods can run)
- Attacker can run privileged containers
- Cluster compromise
- Data theft and service disruption

**With pod security policies:**
- Managed pod security (restricted pods)
- Attacker cannot run privileged containers
- Cluster protected
- Data and services protected

### Problem 2: Weak Pod Security Standards

**Without pod security policies:**
- Weak pod security standards (privileged containers)
- Attacker can escalate privileges
- Cluster compromise
- Data theft and service disruption

**With pod security policies:**
- Strong pod security standards (restricted containers)
- Attacker cannot escalate privileges
- Cluster protected
- Data and services protected

### Problem 3: No Pod Security Policy Monitoring

**Without pod security policies:**
- No pod security policy monitoring
- Pod admission events undetected
- Policy violation events undetected
- Incident response delayed
- Cluster compromise

**With pod security policies:**
- Pod security policy monitoring enabled
- Pod admission events detected
- Policy violation events detected
- Real-time detection
- Rapid incident response
- Cluster protected

### Real-World Impact

**Example: Tesla Kubernetes Breach (2018)**

- **Impact**: Attacker deployed miners across cluster
- **Lesson**: Implement Pod Security Policies

  - No Pod Security Standards monitoring (no audit trail)
- **Example**: Pod Security Standards with baseline profile

**Pod Security Standards Types:**
- **Pod Security Standards (Baseline)**: 
  - Pod Security Standards (baseline)
  - Baseline profile (allow-list)

  - Least privilege

- **Pod Security Standards (Restricted)**: 
  - Pod Security Standards (restricted)
  - Restricted profile (deny-list)
  - Restricted profile enforcement (Pod Security Policies)
  - Least privilege

- **Pod Security Standards (Privileged)**: 
  - Pod Security Standards (privileged)
  - Privileged profile (deny-list)
  - Privileged profile enforcement (Pod Security Policies)
  - Least privilege

**Best Practices:**
- Use Pod Security Standards (baseline, restricted, privileged)
- Implement Pod Security Policies (Pod Security Policies)
- Implement admission control (validating, mutating)
- Implement pod security policy monitoring (pod admission events, policy violations)
- Regular pod security policy audits

**Example**:
```yaml
# Pod Security Standards with baseline profile (secure, advanced)
apiVersion: v1
kind: Namespace
metadata:
  name: secure-namespace
  labels:
    pod-security.kubernetes.io/audit: privileged
    pod-security.kubernetes.io/audit: baseline
    pod-security.kubernetes.io/warn: baseline
    pod-security.kubernetes.io/enforce: baseline
    pod-security.kubernetes.io/enforce-version: latest
---
apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
  namespace: secure-namespace
spec:
  securityContext:
    runAsUser: 1000
    runAsGroup: 1000
    fsGroup: 1000
    seLinuxOptions:
      level: s0:c123,c456
    seccompProfile:
      type: RuntimeDefault
  containers:
  - name: secure-container
    image: nginx:1.14.2
    securityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop:
        - ALL
```
