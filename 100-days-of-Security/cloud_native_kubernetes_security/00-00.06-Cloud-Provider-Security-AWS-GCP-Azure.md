# 00.06 - Cloud Provider Security (AWS / GCP / Azure)

## 1️⃣ What This Topic Is

Cloud Provider Security refers to the security features, best practices, and configurations available on major cloud platforms (AWS, GCP, and Azure) that you can use to secure your cloud-native deployments.

**What this means:**
- Each cloud provider offers security services and features
- You must configure and use these services effectively
- Features vary between providers but principles are similar
- Security is a partnership: provider provides tools, you configure them

**The Three Major Providers:**

1. **AWS (Amazon Web Services)**
   - Most mature cloud platform
   - Extensive security services portfolio
   - Strong compliance certifications

2. **GCP (Google Cloud Platform)**
   - Google's security expertise integrated
   - Machine learning-powered security
   - Unified security platform

3. **Azure (Microsoft Azure)**
   - Integration with Microsoft ecosystem
   - Enterprise-focused security
   - Strong Windows/Linux hybrid capabilities

**Why this matters:**
- Provider security features are foundational to your security posture
- Misconfigured provider security leads to breaches
- You can't build secure applications on insecure cloud foundations
- Provider security features are your responsibility to configure

## 2️⃣ What Problem It Solves

### Problem 1: Securing Cloud Infrastructure

**Without provider security features:**
- Vulnerable network configurations
- Unprotected data storage
- No monitoring or alerting
- Difficult to detect and respond to incidents

**With provider security features:**
- Built-in security services
- Automated threat detection
- Comprehensive monitoring and logging
- Integrated incident response capabilities

### Problem 2: Compliance Requirements

**Without using provider security features:**
- Difficult to meet regulatory requirements
- Manual compliance processes are error-prone
- Audits fail due to missing controls
- Penalties and legal risks

**With provider security features:**
- Pre-built compliance controls
- Automated compliance reporting
- Built-in regulatory certifications
- Easier to demonstrate compliance

### Problem 3: Operational Overhead

**Without provider security features:**
- Must build and maintain custom security tools
- High operational overhead
- Difficult to keep security tools updated
- Resource-intensive security operations

**With provider security features:**
- Managed security services
- Provider maintains and updates tools
- Reduced operational overhead
- Focus on application security, not infrastructure security

### Real-World Impact

**Example: Capital One Breach (2019) - AWS**
- **Available AWS security features not used**: WAF, GuardDuty, Macie
- **Root cause**: Over-privileged IAM role + misconfigured WAF
- **Lesson**: AWS security features existed but weren't configured properly
- **Impact**: 100 million customers' data compromised

**Example: Uber Data Breach (2017) - AWS**
- **Available AWS security features not used**: MFA, IAM policies, CloudTrail
- **Root cause**: Lack of MFA, overly permissive IAM, stolen credentials
- **Lesson**: Basic AWS security features (MFA, IAM) weren't implemented
- **Impact**: 57 million users' data exposed

**Example: Code Spaces Breach (2014) - AWS**
- **Available AWS security features not used**: MFA, CloudTrail, GuardDuty
- **Root cause**: Compromised AWS credentials, no MFA enabled
- **Lesson**: Security features existed but weren't enabled
- **Impact**: Complete data deletion, company shutdown

## 3️⃣ When You Should Use This

### **ALWAYS** - Cloud provider security features should be used in ALL cloud deployments

**When Starting a New Cloud Project:**
- Enable security services from day one
- Configure security groups/firewalls appropriately
- Set up monitoring and logging
- Implement IAM with least privilege

**When Running Production Workloads:**
- Use advanced security features (GuardDuty, Security Command Center)
- Enable automated threat detection
- Set up comprehensive monitoring and alerting
- Regularly review security configurations

**When Facing Compliance Requirements:**
- Use provider compliance certifications
- Enable compliance-related security features
- Use compliance dashboards and reports
- Prepare for audits with provider tools

**When Responding to Incidents:**
- Use provider incident response services
- Leverage provider threat intelligence
- Use provider forensic tools
- Coordinate with provider security team

### Scenarios where this is critical:

**When deploying Kubernetes on cloud:**
- Use provider IAM integration
- Enable provider monitoring (CloudWatch, Cloud Monitoring, Azure Monitor)
- Use provider network security (security groups, firewall rules)
- Use provider secret management (Secrets Manager, Secret Manager, Key Vault)

**When handling sensitive data:**
- Use encryption services (KMS, Cloud KMS, Key Vault)
- Use data loss prevention (Macie, Cloud DLP, Azure Information Protection)
- Use advanced threat detection (GuardDuty, Security Command Center, Defender for Cloud)
- Use compliance reporting

**When securing infrastructure:**
- Use vulnerability scanning (Inspector, Security Scanner, Defender)
- Use network security (security groups, VPC firewalls, Azure Firewall)
- Use identity management (IAM, Cloud IAM, Azure AD)
- Use logging and monitoring (CloudTrail, Audit Logs, Azure Monitor)

## 4️⃣ How It Works (Conceptual)

### AWS Security Services

**Core Security Services:**

1. **IAM (Identity and Access Management)**
   - What it does: Manage users, groups, roles, permissions
   - Why important: Controls who can access what resources
   - Best practices: Least privilege, MFA, regular reviews
   - Key features: Roles, policies, MFA, Access Analyzer

2. **VPC (Virtual Private Cloud)**
   - What it does: Network isolation, subnets, routing
   - Why important: Segments network traffic
   - Best practices: Private subnets for workloads, public only for ingress
   - Key features: Subnets, security groups, NACLs, VPC peering

3. **Security Groups & NACLs**
   - What it does: Firewall rules for network traffic
   - Why important: Controls network access to resources
   - Best practices: Least privilege, regular reviews, monitoring
   - Key features: Stateful rules, IP/port restrictions, protocol filtering

4. **CloudTrail**
   - What it does: Audit logging of AWS API calls
   - Why important: Provides audit trail for security investigations
   - Best practices: Enable for all regions, log to S3, encrypt logs
   - Key features: API call logging, user tracking, event history

5. **GuardDuty**
   - What it does: Threat detection and alerting
   - Why important: Automated threat detection and response
   - Best practices: Enable for all accounts, set up alerts, investigate findings
   - Key features: Anomaly detection, threat intelligence, automated remediation

6. **Macie (Managed Data Classification & Discovery)**
   - What it does: Data classification and discovery
   - Why important: Identifies and protects sensitive data
   - Best practices: Enable for all S3 buckets, classify data, protect PII
   - Key features: Automated classification, PII detection, data catalog

**Advanced Security Services:**

7. **AWS Config**
   - What it does: Configuration monitoring and compliance
   - Why important: Detects configuration drift
   - Best practices: Enable rules, set up alarms, remediate issues
   - Key features: Configuration rules, compliance packs, auto-remediation

8. **AWS Inspector**
   - What it does: Vulnerability scanning
   - Why important: Identifies vulnerabilities in EC2 instances
   - Best practices: Regular scans, remediate findings
   - Key features: CVE detection, network exposure, compliance checks

9. **AWS Shield**
   - What it does: DDoS protection
   - Why important: Protects against DDoS attacks
   - Best practices: Enable for all public-facing services
   - Key features: Layer 3-7 protection, automatic mitigation

10. **WAF (Web Application Firewall)**
    - What it does: Web application protection
    - Why important: Protects against web attacks
    - Best practices: Enable for web apps, customize rules
    - Key features: OWASP protection, IP blocking, rate limiting

11. **KMS (Key Management Service)**
    - What it does: Encryption key management
    - Why important: Secure encryption key storage
    - Best practices: Use for all encrypted resources, rotate keys
    - Key features: Key rotation, BYOK, access controls

12. **Secrets Manager**
    - What it does: Secrets storage and rotation
    - Why important: Secure secrets management
    - Best practices: Store all secrets, enable rotation, use in applications
    - Key features: Automatic rotation, secure storage, versioning

### GCP Security Services

1. **Cloud IAM**
   - What it does: Manage users, roles, permissions
   - Why important: Controls access to GCP resources
   - Best practices: Least privilege, MFA, regular reviews

2. **VPC Network**

3. **Cloud Audit Logs**

4. **Cloud Security Command Center**

5. **Cloud DLP (Data Loss Prevention)**

   - Best practices: Create DLP profiles, inspect data, protect PII
   - Key features: Data classification, content inspection, action rules

**Advanced Security Services:**

6. **Cloud KMS**
   - What it does: Encryption key management
   - Why important: Secure key storage
   - Best practices: Use for all encrypted resources, rotate keys
   - Key features: Key rotation, BYOK, access controls

7. **Secret Manager**
   - What it does: Secrets storage and management

   - Key features: Secure storage, versioning, access controls

8. **Forset Scanner**
   - What it does: Vulnerability scanning

9. **Cloud Armor**

10. **Binary Authorization**

### Azure Security Services

   - Why important: Secure key and secret storage

   - Key features: Key management, secret storage, certificate management

7. **Azure Security Center**
   - What it does: Security posture management
   - Why important: Provides security recommendations
   - Best practices: Enable for all subscriptions, implement recommendations

8. **Azure Sentinel**
   - What it does: SIEM and SOAR
   - Why important: Centralized security monitoring
   - Best practices: Collect all logs, create detection rules

9. **Azure Firewall**
   - What it does: Network firewall
   - Why important: Controls network traffic
   - Best practices: Enable for VNets, configure rules
   - Key features: Application rules, network rules, threat intelligence

10. **Azure Defender for Container Registries**
    - What it does: Container image scanning
    - Why important: Identifies vulnerable images
    - Best practices: Enable for registries, remediate findings
    - Key features: CVE detection, malware detection, compliance

## 6️⃣ Where It Should Be Applied (With Example)

Cloud provider security should be applied **everywhere** in your cloud deployments.

### **1. AWS Security Configuration**

**Example: Securing AWS for Kubernetes (EKS)**

```bash
# 1. Enable MFA (critical first step)
# In AWS Console: IAM → Users → Security credentials → Activate MFA

# 2. Create least privilege IAM policy for EKS
cat > eks-policy.json <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "eks:DescribeCluster",
        "eks:ListClusters"
      ],
      "Resource": "arn:aws:eks:us-west-2:123456789012:cluster/*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:DescribeSecurityGroups",
        "ec2:DescribeSubnets"
      ],
      "Resource": "*"
    }
  ]
}
EOF

aws iam create-policy --policy-name EKSLabPolicy --policy-document file://eks-policy.json

# 3. Enable CloudTrail (audit logging)
aws cloudtrail create-trail \
  --name security-lab-trail \
  --s3-bucket-name cloudtrail-logs \
  --include-global-services \
  --is-multi-region-trail

# 4. Enable GuardDuty (threat detection)
aws guardduty create-detector \
  --enable \
  --data-sources 'S3_LOGS,AWS_KMS'

# 5. Enable AWS Config (configuration monitoring)
aws configservice put-configuration-recorder \
  --configuration-recorder-name config-recorder \
  --role-name AWSConfigRole

# 6. Secure S3 buckets (example)
aws s3api create-bucket --bucket security-lab-bucket
aws s3api put-bucket-acl --bucket security-lab-bucket --acl private
aws s3api put-bucket-encryption --bucket security-lab-bucket \
  --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
```

**AWS Security Best Practices:**

```bash
# Regularly review IAM policies
aws iam list-roles | jq '.Roles[] | select(.AssumeRolePolicyDocument)'

# Review GuardDuty findings regularly
aws guardduty list-findings --detector-id $(aws guardduty list-detectors --query 'DetectorIds[0]' --output text)

# Check for unused IAM roles
aws iam list-roles | jq '.Roles[] | select(.RoleLastUsedDate == null)'

# Review CloudTrail logs for suspicious activity
aws s3 ls s3://cloudtrail-logs/
```

### **2. GCP Security Configuration**

**Example: Securing GCP for Kubernetes (GKE)**

```bash
# 1. Enable MFA
# In GCP Console: IAM & Admin → Security → 2-Step Verification

# 2. Create least privilege IAM role
gcloud iam roles create security_lab_role \
  --title "Security Lab Role" \
  --description "Least privilege for security lab" \
  --permissions='container.clusters.get,container.clusters.list,compute.instances.list,compute.subnetworks.list'

gcloud projects add-iam-policy-binding your-project-id \
  --member="user:your-email@example.com" \
  --role="projects/your-project-id/roles/security_lab_role"

# 3. Enable Cloud Audit Logs
gcloud logging sinks create security-lab-sink \
  --destination logging.googleapis.com/projects/your-project-id \
  --log-filter='protoPayload.methodName!="method_unsupported" AND severity!="DEBUG"'

# 4. Enable Security Command Center
gcloud beta security center settings update \
  --organization=organizations/your-org-id \
  --enable-security-health-analytics

# 5. Enable Cloud KMS (for secrets)
gcloud kms keyrings create security-lab-keyring --location global
gcloud kms keys create eks-key --keyring security-lab-keyring --location global

# 6. Secure Cloud Storage buckets
gsutil mb gs://security-lab-bucket
gsutil iam ch -d users:your-email@example.com gs://security-lab-bucket
```

**GCP Security Best Practices:**

```bash
# Review IAM policies
gcloud projects get-iam-policy your-project-id

# Check Security Command Center findings
gcloud beta security center findings list --organization=organizations/your-org-id

# Enable Forset Scanner for vulnerability scanning
gcloud alpha services enable forset.googleapis.com

# Review audit logs
gcloud logging read 'resource.type="gce_instance"'
```

### **3. Azure Security Configuration**

**Example: Securing Azure for Kubernetes (AKS)**

```bash
# 1. Enable MFA
# In Azure Portal: Azure AD → Security → MFA settings

# 2. Create least privilege role
az role definition create --role-definition aks-role.json
# aks-role.json contains least privilege permissions for AKS

# 3. Assign role to user
az role assignment create \
  --role "AKS Lab Role" \
  --assignee your-email@example.com \
  --scope /subscriptions/your-subscription-id

# 4. Enable Azure Monitor
az monitor log-analytics workspace create \
  --resource-group myResourceGroup \
  --workspace-name security-lab-workspace

# 5. Enable Microsoft Defender for Cloud
az security at-risk update \
  --resource-group myResourceGroup \
  --auto-provision

# 6. Create Key Vault
az keyvault create \
  --name security-lab-vault \
  --resource-group myResourceGroup \
  --location eastus

# 7. Secure Storage account
az storage account create \
  --name securitylabstorage \
  --resource-group myResourceGroup \
  --location eastus \
  --sku Standard_LRS \
  --encryption blob
```

**Azure Security Best Practices:**

```bash
# Review Azure AD roles
az role assignment list --assignee your-email@example.com

# Check Defender alerts
az security alert list

# Review Azure Monitor logs
az monitor activity-log list --max-events 10

# Check Key Vault secrets
az keyvault secret list --vault-name security-lab-vault
```

### **Common Mistakes in Provider Security**

❌ **Mistake 1**: Not enabling MFA
- Reality: MFA is the most effective security control
- Fix: Enable MFA for all users immediately

❌ **Mistake 2**: Using overly permissive IAM policies
- Reality: Overly permissive policies lead to breaches
- Fix: Follow least privilege principle

❌ **Mistake 3**: Not enabling audit logging
- Reality: Can't investigate incidents without logs
- Fix: Enable CloudTrail, Audit Logs, or Monitor immediately

❌ **Mistake 4**: Leaving S3/GCS/Azure Storage public
- Reality: Public buckets cause major breaches
- Fix: Make all storage private, restrict access

❌ **Mistake 5**: Not using threat detection services
- Reality: Manual threat detection is insufficient
- Fix: Enable GuardDuty, Security Command Center, Defender

## 8️⃣ Security Best Practices

### **Do's ✅**

**1. Enable MFA Immediately**
- Enable MFA for all users
- Use hardware tokens for privileged accounts
- Require MFA for all logins
- Use conditional access policies

**2. Follow Least Privilege**
- Create specific roles for specific tasks
- Review IAM policies regularly
- Remove unused permissions
- Use access reviews

**3. Enable Audit Logging**
- Enable CloudTrail, Audit Logs, Azure Monitor
- Log all regions and services
- Encrypt log data
- Export to secure storage

**4. Enable Threat Detection**
- Enable GuardDuty, Security Command Center, Defender
- Configure alerts for critical findings
- Investigate findings promptly
- Automate response when possible

**5. Secure Storage**
- Make all storage private
- Use encryption at rest
- Restrict access with IAM policies
- Enable versioning for important data

**6. Use Secret Management**
- Use Secrets Manager, Secret Manager, Key Vault
- Enable secret rotation
- Never hardcode secrets
- Use IAM roles for secret access

**7. Regular Security Reviews**
- Review IAM policies monthly
- Review security findings weekly
- Review access logs regularly
- Update security configurations

### **Don'ts ❌**

**1. Don't Skip MFA**
- MFA is the most effective security control
- Never disable MFA for convenience
- Require MFA for all users
- Use strong authentication methods

**2. Don't Use Overly Permissive Policies**
- Admin access should be rare
- Specific users for specific tasks
- Review and revoke unused permissions
- Document why each permission is needed

**3. Don't Ignore Audit Logs**
- Logs are critical for incident response
- Set up log retention policies
- Regularly review logs
- Set up alerts for suspicious activity

**4. Don't Leave Storage Public**
- Public storage causes breaches
- Make all storage private by default
- Use bucket policies to restrict access
- Regularly audit storage permissions

**5. Don't Hardcode Secrets**
- Use secret management services
- Never commit secrets to code
- Rotate secrets regularly
- Use IAM roles for access

### **Common Interview Questions**

**Q1: What are the key security services you should enable on AWS, GCP, and Azure?**
**Good Answer**: On all providers, the key services to enable are:
- **Identity & Access Management**: IAM (AWS), Cloud IAM (GCP), Azure AD (Azure) - control access
- **Audit Logging**: CloudTrail (AWS), Cloud Audit Logs (GCP), Azure Monitor (Azure) - provides audit trail
- **Threat Detection**: GuardDuty (AWS), Security Command Center (GCP), Defender for Cloud (Azure) - automated detection
- **Storage Security**: Bucket policies (AWS), IAM policies (GCP), NSGs (Azure) - protect data
- **Secret Management**: Secrets Manager (AWS), Secret Manager (GCP), Key Vault (Azure) - secure secrets
- **Network Security**: Security Groups (AWS), VPC Firewall (GCP), Azure Firewall (Azure) - network protection

These services form the foundation of cloud security. You must configure them properly.

**Q2: How do you integrate Kubernetes (EKS/GKE/AKS) with provider security services?**
**Good Answer**: Integration depends on the provider:
- **AWS EKS**: Use IAM roles for service accounts, CloudTrail for audit logs, GuardDuty for Kubernetes threat detection, Secrets Manager for secrets
- **GCP GKE**: Use Workload Identity for IAM integration, Cloud Audit Logs for Kubernetes events, Security Command Center for threat detection, Secret Manager for secrets
- **Azure AKS**: Use Azure AD for integration, Azure Monitor for logs, Defender for Containers for threat detection, Key Vault for secrets

Key integration points:
- Service account IAM roles
- Audit logging for Kubernetes API calls
- Threat detection for Kubernetes events
- Secret management for application secrets

**Q3: What's the most important security control to enable on cloud providers?**
**Good Answer**: The most important security control is **MFA (Multi-Factor Authentication)**. MFA prevents credential theft, which is the #1 attack vector. Even if you have perfect IAM policies, audit logging, and threat detection, if credentials are stolen without MFA, attackers have full access.

After MFA, the next most important controls are:
1. **Least privilege IAM**: Minimize what attackers can do if they get access
2. **Audit logging**: Detect when access is used
3. **Threat detection**: Automatically detect suspicious activity
4. **Secure storage**: Prevent public data exposure

MFA + least privilege + logging + threat detection = strong security foundation.

**Q4: How do you secure storage (S3/GCS/Azure Storage) on cloud providers?**
**Good Answer**: Securing storage involves:
1. **Make storage private by default**: Never create public buckets
2. **Use IAM policies for access control**: Grant only necessary permissions
3. **Enable encryption at rest**: Use provider encryption services (KMS, Cloud KMS)
4. **Enable versioning**: For important data, enable versioning
5. **Configure lifecycle policies**: Automatically delete old data
6. **Monitor access**: Use audit logs to detect unusual access

Example AWS S3:
- Make bucket private (not public-read)
- Use bucket policy to restrict IP ranges
- Enable encryption (SSE-S3 or SSE-KMS)
- Enable versioning
- Set up lifecycle rules

**Q5: How do you use provider monitoring for Kubernetes security?**
**Good Answer**: Provider monitoring provides visibility into Kubernetes:
- **AWS**: CloudTrail logs EKS API calls, GuardDuty detects Kubernetes threats, CloudWatch monitors cluster metrics
- **GCP**: Cloud Audit Logs logs GKE API calls, Security Command Center detects threats, Cloud Monitoring monitors cluster metrics
- **Azure**: Azure Monitor logs AKS API calls, Defender for Containers detects threats, Azure Monitor monitors cluster metrics

Key monitoring areas:
- Control plane API access (who's accessing Kubernetes API)
- Pod creation and deletion
- Secret access
- Privilege escalation attempts
- Network anomalies
- Resource exhaustion

Set up alerts for suspicious activities like:
- Unusual API access patterns
- Creation of privileged pods
- Secret access from unusual locations
- Failed authentication attempts
