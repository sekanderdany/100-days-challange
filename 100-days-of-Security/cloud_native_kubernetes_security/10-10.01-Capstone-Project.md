# 10.01 - Capstone Project

## 1️⃣ What This Topic Is

The Capstone Project is the culmination of the Cloud Native Kubernetes Security course. It integrates all previous modules (00-09) into a comprehensive, real-world security scenario.

**What this means:**
- **Objective**: Apply knowledge from Foundations, Threats, Cluster Hardening, Control Plane, Identity, Pods, Supply Chain, Runtime, Advanced Topics, and Strategy/Compliance.
- **Scenario**: Secure a multi-tier Kubernetes application from end to end.
- **Deliverables**: Architecture, Configuration, Documentation, and Reporting.

**The Project Requirements:**

1. **Architecture**
   - Design a secure multi-tier application architecture
   - Include security controls for each layer (Cluster, Pods, Network, Supply Chain, Runtime, Strategy)
   - Justify design decisions based on learned principles

2. **Implementation**
   - Create a hardened Kubernetes cluster
   - Implement security controls (Policies, RBAC, Network Policies, mTLS)
   - Deploy monitoring and logging (Metrics, Logs, Traces)

3. **Documentation**
   - Security Architecture Document
   - Security Policy Framework
   - Incident Response Playbook
   - Compliance Audit Report

---

## 2️⃣ The Scenario

**Project: "SecureBank" - A Microservices Banking Platform**

**Application Components:**
1. **Frontend**: Public-facing Web UI (Node.js)
2. **API Gateway**: Gateway to internal services (Nginx/Kong)
3. **Auth Service**: User authentication and token issuance (Go)
4. **Account Service**: Account balances and transactions (Java)
5. **Transaction Service**: Process payments (Python)

**Security Requirements:**
- **Compliance**: SOC 2 Type II, PCI-DSS Level 1
- **Zero Trust**: No implicit trust between services
- **Supply Chain**: All images signed, SBOMs verified
- **Runtime**: Anomaly detection for all processes
- **Strategy**: Defined security governance and metrics

## 3️⃣ Project Tasks

### Phase 1: Strategy & Architecture (Module 09)
- [ ] Define security strategy (Risk Management, Security Vision)
- [ ] Design Zero Trust architecture (mTLS, Service Mesh)
- [ ] Create security governance model (Roles, Responsibilities)
- [ ] Define security metrics and KPIs (MTTR, Vulnerability Age)

### Phase 2: Infrastructure & Control Plane (Modules 02, 03)
- [ ] Harden API Server (TLS, Authentication, Audit Logging)
- [ ] Harden Kubelet (Authorization, Resource Limits)
- [ ] Secure etcd (Encryption, Access Control)
- [ ] Configure Node OS (CIS Benchmarks, File Integrity)

### Phase 3: Identity & Governance (Module 04)
- [ ] Configure OIDC Integration (Dex/Keycloak)
- [ ] Implement RBAC (ClusterRoles, Roles, RoleBindings)
- [ ] Configure Service Accounts (SCCs, Token Requests)
- [ ] Enable Certificate Management (cert-manager, rotation)

### Phase 4: Supply Chain & Images (Module 06)
- [ ] Scan all container images (Trivy, Grype)
- [ ] Sign container images (Cosign, Notation)
- [ ] Generate and verify SBOMs (Syft, SPDX)
- [ ] Configure Admission Controller (Kyverno, OPA Gatekeeper)

### Phase 5: Runtime & Monitoring (Module 07)
- [ ] Apply Seccomp profiles (default, docker-compat)
- [ ] Configure Falco for anomaly detection
- [ ] Deploy monitoring stack (Prometheus, Grafana, Loki)
- [ ] Configure distributed tracing (Jaeger/Tempo)

### Phase 6: Advanced Topics (Module 08)
- [ ] Deploy Service Mesh (Istio Linkerd)
- [ ] Configure mTLS (PeerAuthentication)
- [ ] Implement Serverless Security (Knative, OpenFaaS)
- [ ] Configure Cloud Native Security Tools (CNCF tools)

### Phase 7: Incident Response & Reporting (Module 09)
- [ ] Create Incident Response Playbook
- [ ] Conduct tabletop exercises
- [ ] Generate compliance audit report (SOC 2, PCI-DSS)
- [ ] Create final security dashboard
