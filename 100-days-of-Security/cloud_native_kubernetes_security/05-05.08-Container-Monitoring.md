# 05.08 - Container Monitoring

## 1️⃣ What This Topic Is

Container Monitoring examines security measures for securing Kubernetes container monitoring, understanding metrics, logs, and secure monitoring configurations.

**What this means:**
- Kubernetes Container Monitoring = monitoring stack (Prometheus, Grafana, Loki)
- Container Metrics = resource usage (CPU, memory, storage)
- Container Logs = application logs (stdout, stderr, sidecar)
- Secure monitoring configurations (monitoring policies, alerting)

**The Key Concepts:**

1. **Kubernetes Container Monitoring Areas**
   - Container metrics (resource usage, performance metrics)
   - Container logs (application logs, audit logs, security logs)
   - Monitoring policies (alerting, recording rules)
   - Monitoring compliance (SOC 2, PCI-DSS, HIPAA, GDPR)

2. **Security Principles**
   - Defense in depth (metrics, logs, policies, compliance)
   - Least privilege (monitoring access)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (audit logging)

**Why this matters:**
- Container monitoring is critical for cluster security
- Container monitoring provides visibility into cluster operations
- Container monitoring compromise = cluster-wide compromise
- Container monitoring handles all cluster visibility

## 4️⃣ How It Works (Conceptual)

### Kubernetes Container Monitoring Security Areas

**1. Container Metrics**
- **Purpose**: Monitor container performance
- **Security Measures**: 
  - Container metrics (resource usage, performance metrics)
  - Metrics collection (Prometheus, cAdvisor, kubelet)
  - Metrics security (RBAC, TLS)
  - Metrics policies (alerting, recording rules)
- **Common Misconfigurations**: 
  - No container metrics (no resource usage)
  - Weak metrics security (no RBAC, no TLS)
  - No metrics policies (no alerting)
- **Example**: Container metrics with Prometheus

**Container Metrics Types:**
- **Resource Metrics**: 
  - Resource metrics (CPU usage, memory usage, storage usage)
  - Resource metrics collection (Prometheus, cAdvisor, kubelet)
  - Resource metrics security (RBAC, TLS)
  - Least privilege

- **Performance Metrics**: 
  - Performance metrics (response time, request rate)
  - Performance metrics collection (Prometheus, application metrics)
  - Performance metrics security (RBAC, TLS)
  - Least privilege

**Best Practices:**
- Use container metrics (resource usage, performance metrics)
- Implement metrics collection (Prometheus, cAdvisor, kubelet)
- Implement metrics security (RBAC, TLS)
- Implement metrics policies (alerting, recording rules)
- Regular container metrics audits

**Example**:
```yaml
# Container metrics with Prometheus (secure, advanced)
apiVersion: v1
kind: ConfigMap
metadata:
  name: prometheus-config
  namespace: monitoring
data:
  prometheus.yml: |
    global:
      scrape_interval: 15s
    scrape_configs:
    - job_name: 'kubernetes-pods'
      kubernetes_sd_configs:
      - role: pod
      relabel_configs:
      - source_labels: [__address__, __meta_kubernetes_pod_name__, __meta_kubernetes_pod_namespace__, __meta_kubernetes_pod_label_app]
      regex: __meta_kubernetes_pod_label_app__="([^:]+)(.*)"
      action: replace
      target_label: app
      replacement: '${1}'
```

**2. Container Logs**
- **Purpose**: Monitor container logs
- **Security Measures**: 
  - Container logs (application logs, audit logs, security logs)
  - Log collection (Fluentd, Loki, ELK)
  - Log security (RBAC, TLS, encryption)
  - Log policies (log retention, log archival)
- **Common Misconfigurations**: 
  - No container logs (no application logs)
  - Weak log security (no RBAC, no TLS, no encryption)
  - No log policies (no retention, no archival)
- **Example**: Container logs with Loki

**Container Logs Types:**
- **Application Logs**: 
  - Application logs (stdout, stderr, sidecar)
  - Application log collection (Fluentd, Loki, ELK)
  - Application log security (RBAC, TLS, encryption)
  - Least privilege

- **Audit Logs**: 
  - Audit logs (kube-apiserver audit logs, kubelet audit logs)
  - Audit log collection (Fluentd, Loki, ELK)
  - Audit log security (RBAC, TLS, encryption)
  - Least privilege

- **Security Logs**: 
  - Security logs (Falco, audit logs, network logs)
  - Security log collection (Fluentd, Loki, ELK)
  - Security log security (RBAC, TLS, encryption)
  - Least privilege

**Best Practices:**
- Use container logs (application logs, audit logs, security logs)
- Implement log collection (Fluentd, Loki, ELK)
- Implement log security (RBAC, TLS, encryption)
- Implement log policies (log retention, log archival)
- Regular container logs audits

**Example**:
```yaml
# Container logs with Loki (secure, advanced)
apiVersion: v1
kind: ConfigMap
metadata:
  name: loki-config
  namespace: monitoring
data:
  loki-config.yaml: |
    auth_enabled: false
    limits_config:
      enforce_metric_name: false
      reject_old_samples: true
      reject_old_samples_max_age: 168h
    server:
      http_listen_port: 3100
```

**3. Monitoring Policies**
- **Purpose**: Configure monitoring policies
- **Security Measures**: 
  - Monitoring policies (alerting, recording rules)
  - Monitoring policy enforcement (AlertManager, Prometheus policies)
  - Monitoring policy monitoring (monitoring events, monitoring anomalies)
- **Common Misconfigurations**: 
  - No monitoring policies (no alerting)
  - Weak monitoring policies (allow all)
- **Example**: Monitoring policies with alerting

**Monitoring Policies Types:**
- **Alerting Policies**: 
  - Alerting policies (alert thresholds, alert rules)
  - Alerting enforcement (AlertManager)
  - Least privilege

**Best Practices:**
- Use monitoring policies (alerting, recording rules)
- Implement monitoring policy enforcement (AlertManager, Prometheus policies)
- Regular monitoring policy audits

**Example**:
```yaml
# Monitoring policies with alerting (secure, advanced)
apiVersion: v1
kind: Pod
metadata:
  name: alertmanager
  namespace: monitoring
spec:
  containers:
  - name: alertmanager
    image: prom/alertmanager
    args:
    - '--config.file=/etc/alertmanager/alertmanager.yml'
    - '--storage.path=/alertmanager'
```

**4. Monitoring Alerts**
- **Purpose**: Configure monitoring alerts
- **Security Measures**: 
  - Monitoring alerts (email, Slack, PagerDuty)
  - Alert policies (alert thresholds, alert rules)
  - Alert compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
- **Common Misconfigurations**: 
  - No monitoring alerts (no alerting)
  - No alert policies (no thresholds)
- **Example**: Monitoring alerts with email

**Monitoring Alerts Types:**
- **Email Alerts**: 
  - Email alerts (SMTP, email templates)
  - Email alert policies (alert thresholds, alert rules)
  - Least privilege

- **Slack Alerts**: 
  - Slack alerts (webhooks, message formatting)
  - Slack alert policies (alert thresholds, alert rules)
  - Least privilege

**Best Practices:**
- Use monitoring alerts (email, Slack, PagerDuty)
- Implement alert policies (alert thresholds, alert rules)
- Regular monitoring alerts audits

**Example**:
```yaml
# Monitoring alerts with Slack (secure, advanced)
apiVersion: v1
kind: Secret
metadata:
  name: alertmanager-slack
  namespace: monitoring
type: Opaque
stringData:
  slack-webhook: 'https://hooks.slack.com/services/YOUR-WEBHOOK-ID'
```

## 6️⃣ Where It Should Be Applied (With Example)

Container monitoring should guide **ALL Kubernetes deployments**.

### **1. Applying Container Metrics**

**Example: Configure Container Metrics**

```bash
echo "=== Container Metrics Configuration (Advanced) ==="

# 1. Install Prometheus Operator
kubectl apply -f https://raw.githubusercontent.com/prometheus-operator/prometheus-operator/main/bundle.yaml

# 2. Create Prometheus instance
kubectl apply -f - <<EOF
apiVersion: monitoring.coreos.com/v1
kind: Prometheus
metadata:
  name: k8s
  namespace: monitoring
spec:
  replicas: 2
  serviceAccountName: prometheus
  serviceMonitorSelector:
    matchLabels:
      release: prometheus-operator
  retention: 15d
  resources:
    requests:
      memory: 400Mi
EOF

# 3. Verify container metrics
kubectl get prometheus -n monitoring

# DOCUMENT: What container metrics did you configure?
```
