# 06.02 - Container Image Signing

## 1️⃣ What This Topic Is

Container Image Signing examines security measures for securing Kubernetes container images, understanding image signing, verification, and secure image signing configurations.

**What this means:**
- Kubernetes Container Images = container artifacts (Docker images, OCI images)
- Image Signing = image signatures (cosign, docker trust, notation)
- Image Verification = image signature verification (signature checks, notary, trust policies)
- Secure image signing configurations (signing keys, verification policies, trust store)

**The Key Concepts:**

1. **Kubernetes Container Image Signing Areas**
   - Image signing (cosign, docker trust, notation)
   - Image verification (signature checks, notary, trust policies)
   - Signing keys (key management, key rotation, key storage)
   - Image signing compliance (SOC 2, PCI-DSS, HIPAA, GDPR)

2. **Security Principles**
   - Defense in depth (signing, verification, keys, compliance)
   - Least privilege (signing access)
   - Zero-trust (never trust, always verify)
   - Immutable infrastructure (immutable tags, immutable infrastructure)
   - Audit everything (audit logging)

**Why this matters:**
- Container image signing is critical for cluster security
- Container image signing proves image integrity
- Container image signing is required for regulations
- Container image signing handles all image integrity

## 2️⃣ What Problem It Solves

### Problem 1: Unmanaged Image Signing

**Without image signing:**
- Unmanaged image signing (no signatures, no verification)
- Attacker can tamper with images
- Cluster compromise
- Data theft and service disruption

**With image signing:**
- Managed image signing (signatures, verification, trust policies)
- Attacker cannot tamper with images
- Cluster protected
- Data and services protected

### Problem 2: No Image Verification

**Without image signing:**
- No image verification (no signature checks, no trust policies)
- Cluster cannot verify image integrity
- Cluster instability
- Data theft and service disruption

**With image signing:**
- Image verification enabled (signature checks, trust policies)
- Cluster can verify image integrity
- Cluster stable
- Data and services protected

### Problem 3: No Signing Keys

**Without image signing:**
- No signing keys (no key management, no key rotation)
- Attacker can compromise signing keys
- Cluster compromise
- Data theft and service disruption

**With image signing:**
- Signing keys enabled (key management, key rotation, key storage)
- Attacker cannot compromise signing keys
- Cluster protected
- Data and services protected

## 4️⃣ How It Works (Conceptual)

### Kubernetes Container Image Signing Areas

**1. Image Signing**
- **Purpose**: Sign container images
- **Security Measures**: 
  - Image signing (cosign, docker trust, notation)
  - Signing keys (key management, key rotation, key storage)
  - Image signing compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Image signing audit (signing logs, signing reports)
- **Common Misconfigurations**: 
  - No image signing (no signatures, no verification)
  - Weak signing keys (no key rotation, insecure storage)
  - No image signing compliance (no SOC 2, no PCI-DSS, no HIPAA, no GDPR)
- **Example**: Image signing with cosign

**Image Signing Types:**
- **Cosign**: 
  - Cosign (cosign, sigstore, rekor)
  - Cosign security (key management, key rotation, key storage)
  - Cosign compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Least privilege

- **Docker Trust**: 
  - Docker trust (docker trust, docker notary, docker content trust)
  - Docker trust security (key management, key rotation, key storage)
  - Docker trust compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Least privilege

- **Notation**: 
  - Notation (notation, sigstore, TUF)
  - Notation security (key management, key rotation, key storage)
  - Notation compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Least privilege

**Best Practices:**
- Use image signing (cosign, docker trust, notation)
- Implement signing keys (key management, key rotation, key storage)
- Implement image verification (signature checks, trust policies)
- Regular image signing audits

**Example**:
```bash
# Image signing with cosign (secure, advanced)
cosign sign --key cosign.key <image-name>
```

**2. Image Verification**
- **Purpose**: Verify container images
- **Security Measures**: 
  - Image verification (signature checks, notary, trust policies)
  - Verification policies (trust policies, signature checks)
  - Verification compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Verification audit (verification logs, verification reports)
- **Common Misconfigurations**: 
  - No image verification (no signature checks, no trust policies)
  - Weak verification policies (allow all)
  - No verification compliance (no SOC 2, no PCI-DSS, no HIPAA, no GDPR)
- **Example**: Image verification with cosign

**Image Verification Types:**
- **Signature Checks**: 
  - Signature checks (signature verification, signature validation)
  - Signature check policies (trust policies, signature checks)
  - Least privilege

- **Notary**: 
  - Notary (notary, TUF, Rekor)
  - Notary security (key management, key rotation, key storage)
  - Notary compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Least privilege

- **Trust Policies**: 
  - Trust policies (trust policies, trust stores)
  - Trust policy security (key management, key rotation, key storage)
  - Least privilege

**Best Practices:**
- Use image verification (signature checks, trust policies)
- Implement verification policies (trust policies, signature checks)
- Implement verification compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
- Regular image verification audits

**Example**:
```bash
# Image verification with cosign (secure, advanced)
cosign verify --key cosign.pub <image-name>
```

**3. Signing Keys**
- **Purpose**: Manage signing keys
- **Security Measures**: 
  - Signing keys (key management, key rotation, key storage)
  - Key policies (access control, encryption)
  - Key compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
  - Key audit (key access logs, key usage logs)
- **Common Misconfigurations**: 
  - No signing keys (no key management, no key rotation)
  - Weak key policies (no access control, no encryption)
  - No key compliance (no SOC 2, no PCI-DSS, no HIPAA, no GDPR)
- **Example**: Signing keys with cosign

**Signing Keys Types:**
- **Key Management**: 
  - Key management (key generation, key storage, key rotation)
  - Key management tools (AWS KMS, GCP KMS, Azure Key Vault)
  - Least privilege

- **Key Rotation**: 
  - Key rotation (key rotation, key revocation, key expiration)
  - Key rotation tools (cosign, docker trust, notation)
  - Least privilege

**Best Practices:**
- Use signing keys (key management, key rotation, key storage)
- Implement key policies (access control, encryption)
- Implement key compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
- Regular signing key audits

**Example**:
```bash
# Signing keys with cosign (secure, advanced)
cosign generate-key-pair cosign.key cosign.pub
```
