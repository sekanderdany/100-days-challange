# 03.09 - Control Plane and Node Monitoring

## 1️⃣ What This Topic Is

Control Plane and Node Monitoring Security examines security measures for monitoring Kubernetes control plane and node components, understanding monitoring security, alerting, and logging.

**What this means:**
- Control plane and node monitoring = security observability
- Defense in depth for monitoring
- Least privilege for monitoring
- Secure monitoring configurations

**The Key Concepts:**

1. **Control Plane and Node Monitoring Security Areas**
   - Control plane monitoring (API server, scheduler, controller manager)
   - Node monitoring (kubelet, container runtime, node OS)
   - Alerting (Prometheus, AlertManager)
   - Audit logging (CloudTrail, Cloud Audit Logs, Monitor)
   - Security monitoring (Falco, Sysdig)

2. **Security Principles**
   - Defense in depth (monitoring, alerting, logging)
   - Least privilege (monitoring permissions)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (audit logging)

**Why this matters:**
- Monitoring is essential for security observability
- Monitoring is primary attack detection mechanism
- Monitoring compromise = security blindness
- Monitoring handles all security events

## 4️⃣ How It Works (Conceptual)

### Control Plane and Node Monitoring Security Areas

- **Security Measures**: 
  - API server metrics
  - Scheduler metrics
  - Controller manager metrics
  - Cloud controller manager metrics
  - Control plane logs
- **Common Misconfigurations**: 
  - No control plane metrics (all metrics disabled)
  - No control plane logs (all logs disabled)
  - Over-privileged monitoring access
  - No monitoring retention (logs deleted immediately)
- **Example**: Control plane monitoring with Prometheus

**Control Plane Monitoring Types:**
- **API Server Metrics**: 
  - Request metrics
  - Latency metrics
  - Error metrics
  - Resource metrics

- **Scheduler Metrics**: 
  - Scheduling metrics
  - Scheduling latency
  - Scheduling errors
  - Resource metrics

- **Controller Manager Metrics**: 
  - Controller metrics
  - Controller latency
  - Controller errors
  - Resource metrics

- **Cloud Controller Manager Metrics**: 
  - Cloud provider metrics
  - Cloud provider latency
  - Cloud provider errors
  - Resource metrics

- **Control Plane Logs**: 
  - API server logs
  - Scheduler logs
  - Controller manager logs
  - Cloud controller manager logs
  - Audit logs

**Best Practices:**
- Enable control plane metrics
- Enable control plane logs
- Enable monitoring retention
- Implement alerting
- Monitor for security events

**Example**:
```yaml
# Control plane monitoring with Prometheus (secure, advanced)
apiVersion: v1
kind: Pod
metadata:
  name: prometheus-control-plane
  namespace: monitoring
spec:
  containers:
  - name: prometheus
    image: prom/prometheus:v2.45.0
    args:
    - --config.file=/etc/prometheus/prometheus.yml
    - --storage.tsdb.retention.time=30d
    - --storage.tsdb.retention.size=10GB
    - --web.enable-lifecycle
    ports:
    - containerPort: 9090
    volumeMounts:
    - name: config-volume
    - name: storage-volume
    - name: rules-volume
    volumes:
    - name: config-volume
      configMap:
        name: prometheus-config
    - name: storage-volume
      persistentVolumeClaim:
        claimName: prometheus-pvc
    - name: rules-volume
      configMap:
        name: prometheus-rules
```

**Best Practices:**
- Enable node metrics
- Enable node logs
- Enable monitoring retention
- Implement alerting
- Monitor for security events
- Enable security logging (Falco, Sysdig)

**Example**:
```yaml
# Node monitoring with Prometheus and Falco (secure, advanced)
apiVersion: v1
kind: DaemonSet
metadata:
  name: falco
  namespace: monitoring
spec:
  selector:
    matchLabels:
      app: falco
  template:
    metadata:
      labels:
        app: falco
    spec:
      serviceAccountName: falco
      hostPID: true
      containers:
      - name: falco
        image: falcosecurity/falco:latest
        args:
        - /usr/bin/falco
        - /etc/falco/falco.yaml
        securityContext:
          privileged: true
        volumeMounts:
        - name: device-volume
          mountPath: /host/dev
          readOnly: true
        - name: proc-volume
          mountPath: /host/proc
          readOnly: true
        - name: cgroup-volume
          mountPath: /host/sys/fs/cgroup
          readOnly: true
        volumes:
        - name: device-volume
          hostPath:
            path: /dev
        - name: proc-volume
          hostPath:
            path: /proc
        - name: cgroup-volume
          hostPath:
            path: /sys/fs/cgroup
```

**Example**:
```yaml
# Alerting with Prometheus and AlertManager (secure, advanced)
apiVersion: v1
kind: ConfigMap
metadata:
  name: prometheus-rules
  namespace: monitoring
data:
  alert.rules: |
    groups:
    - name: security_alerts
      rules:
      - alert: RootLogin
        expr: count(logged_in(user="root")) > 0
        for: 5m
        labels:
          severity: critical
          team: security
      - alert: PodContainerEscalation
        expr: rate(kube_pod_container_status_restarts_total[5m]) > 0
        for: 5m
        labels:
          severity: critical
          team: security
---
apiVersion: v1
kind: Deployment
metadata:
  name: alertmanager
  namespace: monitoring
spec:
  replicas: 1
  selector:
    matchLabels:
      app: alertmanager
  template:
    metadata:
      labels:
        app: alertmanager
    spec:
      containers:
      - name: alertmanager
        image: prom/alertmanager:v0.25.0
        args:
        - --config.file=/etc/alertmanager/alertmanager.yml
        - --storage.path=/alertmanager
        ports:
        - containerPort: 9093
        volumeMounts:
        - name: config-volume
        - name: storage-volume
        - name: templates-volume
        volumes:
        - name: config-volume
          configMap:
            name: alertmanager-config
        - name: storage-volume
          emptyDir: {}
        - name: templates-volume
          configMap:
            name: alertmanager-templates
```
