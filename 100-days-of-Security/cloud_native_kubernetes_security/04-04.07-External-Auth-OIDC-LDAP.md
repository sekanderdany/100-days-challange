# 04.07 - External Auth (OIDC, LDAP)

## 1️⃣ What This Topic Is

External Auth (OIDC, LDAP) examines security measures for securing Kubernetes external authentication, understanding OIDC authentication, LDAP authentication, and secure external authentication configurations.

**What this means:**
- Kubernetes external auth = external identity providers (OIDC, LDAP)
- OIDC = OpenID Connect (identity layer on top of OAuth 2.0)
- LDAP = Lightweight Directory Access Protocol (directory services)
- Secure external auth configurations (SSO, RBAC, ABAC)

**The Key Concepts:**

1. **Kubernetes External Auth Mechanisms**
   - OIDC authentication (OpenID Connect)
   - LDAP authentication (Lightweight Directory Access Protocol)
   - SSO integration (Single Sign-On)
   - External auth security (RBAC, ABAC)
   - External auth monitoring (authentication events, authorization events)

2. **Security Principles**
   - Defense in depth (OIDC, LDAP, SSO, RBAC, ABAC, monitoring)
   - Least privilege (external auth permissions)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (audit logging)

**Why this matters:**
- External auth is critical for cluster security
- External auth controls all human access to cluster resources
- External auth compromise = cluster-wide compromise
- External auth handles all external authentication

## 2️⃣ What Problem It Solves

### Problem 1: Unmanaged External Auth

**Without external auth security:**
- Unmanaged external auth (OIDC, LDAP)
- Attacker can bypass external auth
- Cluster compromise
- Data theft and service disruption

**With external auth security:**
- Managed external auth (OIDC, LDAP)
- Attacker cannot bypass external auth
- Cluster protected
- Data and services protected

### Problem 2: Weak External Auth

**Without external auth security:**
- Weak external auth (plaintext authentication)
- Attacker can steal external auth credentials
- Cluster compromise
- Data theft and service disruption

**With external auth security:**
- Strong external auth (OIDC, LDAP)
- Attacker cannot steal external auth credentials
- Cluster protected
- Data and services protected

### Problem 3: No External Auth Monitoring

**Without external auth security:**
- No external auth monitoring
- External auth events undetected
- External auth incidents undetected
- Incident response delayed
- Cluster compromise

**With external auth security:**
- External auth monitoring enabled
- External auth events detected
- External auth incidents detected
- Real-time detection
- Rapid incident response
- Cluster protected

### Real-World Impact

**Example: Tesla Kubernetes Breach (2018)**
- **Vulnerability**: Weak external auth (OIDC)
- **Root cause**: No SSO integration
- **External auth issue**: Attacker bypassed OIDC authentication
- **Impact**: Attacker deployed miners across cluster
- **Lesson**: Implement SSO integration (OIDC)

**Example: Uber Data Breach (2016)**
- **Vulnerability**: Unmanaged external auth (LDAP)
- **Root cause**: No LDAP management
- **External auth issue**: Attacker impersonated cluster-admin
- **Impact**: 57 million customer records accessed
- **Lesson**: Implement external auth management (LDAP)

**Example: Capital One Breach (2019)**
- **Vulnerability**: No external auth monitoring
- **Root cause**: No external auth audit logging
- **External auth issue**: External auth events undetected
- **Impact**: 106 million customer records accessed
- **Lesson**: Implement external auth monitoring

## 4️⃣ How It Works (Conceptual)

### Kubernetes External Auth Mechanisms

**1. OIDC Authentication**
- **Purpose**: Provide OpenID Connect authentication for Kubernetes API
- **Security Measures**: 
  - OIDC providers (Okta, Auth0, Keycloak)
  - OIDC ID tokens
  - OIDC access tokens
  - OIDC refresh tokens
  - SSO integration
  - User token management
- **Common Misconfigurations**: 
  - No OIDC providers (no external auth)
  - Weak OIDC configuration (insecure providers)
  - No SSO integration (username/password)
  - Long-lived OIDC tokens
  - No OIDC token rotation
- **Example**: OIDC authentication with OpenID Connect

**OIDC Authentication Types:**
- **OIDC Providers**: 
  - OIDC providers (Okta, Auth0, Keycloak)
  - OIDC ID tokens
  - OIDC access tokens
  - SSO integration
  - User token management

- **OIDC ID Tokens**: 
  - OIDC ID tokens (short-lived)
  - OIDC access tokens
  - OIDC refresh tokens
  - SSO integration
  - User token management

- **OIDC Access Tokens**: 
  - OIDC access tokens (short-lived)
  - OIDC ID tokens
  - OIDC refresh tokens
  - SSO integration
  - User token management

- **OIDC Refresh Tokens**: 
  - OIDC refresh tokens (long-lived)
  - OIDC ID tokens
  - OIDC access tokens
  - SSO integration
  - User token management

**Best Practices:**
- Use OIDC providers (Okta, Auth0, Keycloak)
- Implement SSO integration
- Implement user token management
- Regular OIDC audits

**Example**:
```yaml
# OIDC authentication with OpenID Connect (secure, advanced)
# This would be configured via API server flags
# For example, using static configuration files:
# --oidc-issuer-url=https://oidc.example.com
# --oidc-client-id=kubernetes
# --oidc-username-claim=email
# --oidc-groups-claim=groups
# --oidc-ca-file=/etc/kubernetes/pki/oidc-ca.crt
# --oidc-signing-key-file=/etc/kubernetes/pki/oidc-signing.key

# Example OIDC configuration file (kube-apiserver.yaml)
apiVersion: v1
kind: ConfigMap
metadata:
  name: oidc-config
  namespace: kube-system
data:
  oidc-config.yaml: |
    issuer: https://oidc.example.com
    clientID: kubernetes
    usernameClaim: email
    groupsClaim: groups
    caFile: /etc/kubernetes/pki/oidc-ca.crt
    signingKeyFile: /etc/kubernetes/pki/oidc-signing.key
```

```yaml
# --ldap-port=636

# --ldap-bind-dn=cn=admin,dc=example,dc=com
# --ldap-bind-password=secret
# --ldap-user-search-base=ou=users,dc=example,dc=com
# --ldap-user-search-filter=(objectClass=inetOrgPerson)
# --ldap-group-search-base=ou=groups,dc=example,dc=com

# --ldap-group-search-user-attribute=uid

# Example LDAP configuration file (kube-apiserver.yaml)
apiVersion: v1
kind: ConfigMap
metadata:
  name: ldap-config
  namespace: kube-system
data:
  ldap-config.yaml: |
    host: ldap.example.com
    port: 636
    baseDN: dc=example,dc=com
    bindDN: cn=admin,dc=example,dc=com
    bindPassword: secret
    userSearchBase: ou=users,dc=example,dc=com
    userSearchFilter: (objectClass=inetOrgPerson)
    groupSearchBase: ou=groups,dc=example,dc=com
    groupSearchFilter: (objectClass=groupOfNames)
    groupSearchUserAttribute: uid
```
