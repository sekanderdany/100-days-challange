# 03.04 - Controller Manager Security

## 1️⃣ What This Topic Is

Controller Manager Security examines security measures for securing Kubernetes controller manager, understanding controller manager security, controller isolation, and advanced configurations.

**What this means:**
- Controller manager security = securing Kubernetes state management
- Defense in depth for controller manager
- Least privilege for controller manager
- Secure controller manager configurations

**The Key Concepts:**

1. **Controller Manager Security Areas**
   - Controller manager authentication (mTLS, client certificates)
   - Controller manager authorization (RBAC, webhook)
   - Controller manager encryption (at rest and in transit)
   - Controller isolation (namespace-level, tenant-level)
   - Controller manager monitoring

2. **Security Principles**
   - Defense in depth (authentication, authorization, encryption)
   - Least privilege (controller manager permissions)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (audit logging)

**Why this matters:**
- Controller manager manages cluster state
- Controller manager is primary attack target
- Controller manager compromise = cluster compromise
- Controller manager handles all cluster controllers

---

## 2️⃣ What Problem It Solves

### Problem 1: Unauthenticated Controller Manager Access

**Without controller manager security:**
- Unauthenticated controller manager access
- Attacker can access controller manager
- Cluster state compromise
- Data theft and service disruption

**With controller manager security:**
- Controller manager authentication required (mTLS, client certificates)
- Unauthorized access prevented
- Cluster protected

### Problem 2: Over-Privileged Controller Manager Access

**Without controller manager security:**
- Over-privileged controller manager access
- Attacker can escalate privileges
- Cluster-wide compromise
- Data theft and service disruption

**With controller manager security:**
- Least privilege controller manager access (RBAC, webhook)
- Privilege escalation prevented
- Cluster protected

### Problem 3: Controller Manager Denial of Service

**Without controller manager security:**
- No controller manager rate limiting
- Attacker can DoS controller manager
- Cluster disruption
- Service unavailability

**With controller manager security:**
- Controller manager rate limiting implemented
- DoS attacks prevented
- Cluster protected

### Real-World Impact

**Example: Tesla Kubernetes Breach (2018)**
- **Vulnerability**: Unauthenticated controller manager
- **Root cause**: No controller manager authentication
- **Controller manager issue**: Attacker accessed controller manager without authentication
- **Impact**: Attacker deployed miners across cluster
- **Lesson**: Configure controller manager authentication

**Example: Uber Data Breach (2016)**
- **Vulnerability**: Over-privileged controller manager access
- **Root cause**: No controller manager least privilege
- **Controller manager issue**: Attacker escalated to cluster-admin
- **Impact**: 57 million customer records accessed
- **Lesson**: Configure controller manager least privilege

**Example: Capital One Breach (2019)**
- **Vulnerability**: Controller manager DoS
- **Root cause**: No controller manager rate limiting
- **Controller manager issue**: Attacker DoSed controller manager
- **Impact**: Service disruption, data access
- **Lesson**: Configure controller manager rate limiting

## 4️⃣ How It Works (Conceptual)

### Controller Manager Security Areas

**1. Controller Manager Authentication**
- **Purpose**: Verify who can access controller manager
- **Security Measures**: 
  - mTLS (mutual TLS)
  - Client certificate authentication
  - Token-based authentication (service accounts)
  - Anonymous access (disabled)
- **Common Misconfigurations**: 
  - No controller manager authentication (all access allowed)
  - Weak authentication (weak certificates)
  - Anonymous access enabled
  - Long-lived tokens
  - Weak TLS (outdated protocols, weak ciphers)
- **Example**: Controller manager with mTLS and client certificates

**Controller Manager Authentication Types:**
- **mTLS (Mutual TLS)**: 
  - Controller manager verifies client certificates
  - Client verifies controller manager certificates
  - Prevents man-in-the-middle attacks
  - Prevents unauthorized access

- **Client Certificates**: 
  - X.509 certificates
  - Certificate-based authentication
  - Certificate rotation
  - Revocation

- **Token-Based Authentication**: 
  - Service account tokens
  - Bearer tokens
  - Short-lived tokens
  - Token rotation

**Best Practices:**
- Use mTLS for controller manager
- Use client certificate authentication
- Use short-lived tokens
- Implement certificate rotation
- Use strong TLS (TLS 1.3, strong ciphers)
- Disable anonymous access

**Example**:
```yaml
# Controller manager with mTLS (secure)
apiVersion: v1
kind: Pod
metadata:
  name: kube-controller-manager
  namespace: kube-system
spec:
  containers:
  - name: kube-controller-manager
    image: k8s.gcr.io/kube-controller-manager:v1.27.0
    args:
    - --authentication-kubeconfig=/etc/kubernetes/controller-manager.conf
    - --authorization-kubeconfig=/etc/kubernetes/controller-manager.conf
    - --client-ca-file=/etc/kubernetes/pki/client-ca.crt
    - --tls-cert-file=/etc/kubernetes/pki/controller-manager.crt
    - --tls-private-key-file=/etc/kubernetes/pki/controller-manager.key
    - --tls-min-version=VersionTLS13
    - --tls-cipher-suites=TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256,TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256
```

**2. Controller Manager Authorization**
- **Purpose**: Control what can be done with controller manager
- **Security Measures**: 
  - RBAC (Role-Based Access Control)
  - Authorization webhook
  - Namespace-based authorization
  - Resource-based authorization
  - Default-deny with explicit allow
- **Common Misconfigurations**: 
  - No controller manager authorization (all access allowed)
  - Over-privileged RBAC
  - No resource-based authorization
  - No namespace-based authorization
- **Example**: Controller manager with RBAC and webhook

**Controller Manager Authorization Types:**
- **RBAC (Role-Based Access Control)**: 
  - Cluster roles (cluster-wide permissions)
  - Roles (namespace permissions)
  - Role bindings (associate roles with subjects)
  - Cluster role bindings
  - Least privilege

- **Authorization Webhook**: 
  - External webhook validates requests
  - Rejects or allows requests
  - Flexible authorization

- **Namespace-Based Authorization**: 
  - Namespace-level permissions
  - Tenant-level isolation
  - Least privilege

- **Resource-Based Authorization**: 
  - Resource-level permissions
  - Fine-grained permissions
  - Least privilege

**Best Practices:**
- Use least privilege RBAC
- Use authorization webhook for flexibility
- Use namespace-based authorization for multi-tenancy
- Use resource-based authorization for fine-grained control
- Regular RBAC audits

**Example**:
```yaml
# Controller manager RBAC (least privilege)
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: controller-manager-reader
rules:
- nonResourceURLs:
  - /healthz
  verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: controller-manager-reader-binding
subjects:
- kind: ServiceAccount
  name: controller-manager-reader
roleRef:
  kind: ClusterRole
  name: controller-manager-reader
  apiGroup: rbac.authorization.k8s.io
```

**3. Controller Isolation**
- **Purpose**: Isolate controllers from each other
- **Security Measures**: 
  - Namespace-level controller isolation
  - Tenant-level controller isolation
  - Resource-level controller isolation
  - Controller manager least privilege
- **Common Misconfigurations**: 
  - No controller isolation (all controllers in same namespace)
  - No tenant-level controller isolation
  - No resource-level controller isolation
  - Over-privileged controller manager
- **Example**: Namespace-level controller isolation

**Controller Isolation Types:**
- **Namespace-Level Controller Isolation**: 
  - Namespace-level controller isolation
  - Namespace-level controller RBAC
  - Namespace-level controller least privilege
  - Tenant-level isolation

- **Tenant-Level Controller Isolation**: 
  - Tenant-level controller isolation
  - Tenant-level controller RBAC
  - Tenant-level controller least privilege
  - Namespace-level isolation

- **Resource-Level Controller Isolation**: 
  - Resource-level controller isolation
  - Resource-level controller RBAC
  - Resource-level controller least privilege
  - Namespace-level isolation

**Best Practices:**
- Implement namespace-level controller isolation
- Implement tenant-level controller isolation
- Implement resource-level controller isolation
- Implement controller least privilege
- Implement controller monitoring

**Example**:
```yaml
# Namespace-level controller isolation (secure)
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: controller-isolation
  namespace: kube-system
spec:
  podSelector:
    matchLabels:
      tier: control-plane
  policyTypes: [Ingress, Egress]
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: kube-system
  egress:
  - to:
    - namespaceSelector:
        matchLabels:
          name: kube-system
```

**4. Controller Manager Encryption**
- **Purpose**: Encrypt controller manager data and communication
- **Security Measures**: 
  - Controller manager to API server encryption (mTLS)
  - Controller manager to kubelet encryption (mTLS)
  - Controller manager encryption at rest
  - Controller manager encryption in transit
- **Common Misconfigurations**: 
  - No controller manager encryption (plaintext communication)
  - Weak TLS (outdated protocols, weak ciphers)
  - No mTLS for controller manager communication
  - No encryption at rest
- **Example**: Controller manager with encryption

**Controller Manager Encryption Types:**
- **Controller Manager to API Server Encryption**: 
  - mTLS for controller manager to API server
  - Certificate-based authentication
  - Encryption key rotation

- **Controller Manager to Kubelet Encryption**: 
  - mTLS for controller manager to kubelet
  - Certificate-based authentication
  - Encryption key rotation

- **Controller Manager Encryption at Rest**: 
  - Controller manager secrets encryption
  - KMS encryption
  - Encryption key rotation

**Best Practices:**
- Use TLS 1.3 or higher
- Use strong ciphers
- Use strong key exchange (ECDHE, etc.)
- Use certificate-based authentication
- Implement certificate rotation
- Use KMS for encryption at rest

**Example**:
```yaml
# Controller manager encryption (secure)
apiVersion: v1
kind: Pod
metadata:
  name: kube-controller-manager
  namespace: kube-system
spec:
  containers:
  - name: kube-controller-manager
    image: k8s.gcr.io/kube-controller-manager:v1.27.0
    args:
    - --kubeconfig=/etc/kubernetes/controller-manager.conf
    - --client-ca-file=/etc/kubernetes/pki/client-ca.crt
    - --tls-cert-file=/etc/kubernetes/pki/controller-manager.crt
    - --tls-private-key-file=/etc/kubernetes/pki/controller-manager.key
    - --tls-min-version=VersionTLS13
    - --tls-cipher-suites=TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256,TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256
```
