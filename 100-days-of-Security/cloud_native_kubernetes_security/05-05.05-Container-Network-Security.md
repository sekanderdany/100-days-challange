# 05.05 - Container Network Security

## 1️⃣ What This Topic Is

Container Network Security examines security measures for securing Kubernetes container networks, understanding network policies, segmentation, and secure network configurations.

**What this means:**
- Kubernetes Container Networks = network policies (NetworkPolicies)
- Network Segmentation = namespace isolation (namespace policies, pod policies)
- Network Plugins = CNI plugins (Calico, Cilium, Weave Net)
- Secure network configurations (network policies, network monitoring)

**The Key Concepts:**

1. **Kubernetes Container Network Security Areas**
   - Network policies (NetworkPolicies)
   - Network segmentation (namespace isolation, pod isolation)
   - Network plugins (CNI: Calico, Cilium, Weave Net)
   - Network monitoring (network policies, network flows)

2. **Security Principles**
   - Defense in depth (policies, segmentation, plugins, monitoring)
   - Least privilege (network access)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (audit logging)

**Why this matters:**
- Container networks are critical for cluster security
- Container networks control all network traffic
- Container networks compromise = cluster-wide compromise

## 2️⃣ What Problem It Solves

### Problem 1: Unmanaged Network Policies

**Without network security:**
- Unmanaged network policies (all pods can communicate)
- Attacker can move laterally
- Cluster compromise
- Data theft and service disruption

**With network security:**
- Managed network policies (NetworkPolicies)
- Attacker cannot move laterally
- Cluster protected
- Data and services protected

### Problem 2: No Network Segmentation

**Without network security:**
- No network segmentation (all namespaces can communicate)
- Attacker can move laterally
- Cluster compromise
- Data theft and service disruption

**With network security:**
- Network segmentation enabled (namespace isolation, pod isolation)
- Attacker cannot move laterally
- Cluster protected
- Data and services protected

## 4️⃣ How It Works (Conceptual)

### Kubernetes Container Network Security Areas

**1. Network Policies**
- **Purpose**: Control pod-to-pod communication
- **Security Measures**: 
  - Network policies (NetworkPolicies)
  - Network policy enforcement (deny all, allow explicitly)
- **Common Misconfigurations**: 
  - No network policies (allow all)
  - Weak network policies (allow all)
- **Example**: Network policies with default-deny

**Network Policies Types:**
- **Default-Deny**: 
  - Default-deny (deny all ingress, deny all egress)
  - Default-deny enforcement (allow-list, deny-list)
  - Least privilege

**Best Practices:**
- Use network policies (NetworkPolicies)
- Implement default-deny (deny all ingress, deny all egress)
- Regular network policy audits

**Example**:
```yaml
# Network policies with default-deny (secure, advanced)
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all-ingress
  namespace: secure-namespace
spec:
  podSelector: {}
  policyTypes:
  - Ingress
```

**2. Network Segmentation**
- **Purpose**: Isolate network traffic
- **Security Measures**: 
  - Network segmentation (namespace isolation, pod isolation)
  - Network segmentation enforcement (network policies)
- **Common Misconfigurations**: 
  - No network segmentation (allow all)
  - Weak network segmentation (allow all)
- **Example**: Network segmentation with namespace isolation

**Network Segmentation Types:**
- **Namespace Isolation**: 
  - Namespace isolation (namespace policies, pod policies)
  - Namespace isolation enforcement (network policies)
  - Least privilege

**Best Practices:**
- Use network segmentation (namespace isolation, pod isolation)
- Implement network segmentation enforcement (network policies)
- Regular network segmentation audits

**Example**:
```yaml
# Network segmentation with namespace isolation (secure, advanced)
apiVersion: v1
kind: Namespace
metadata:
  name: secure-namespace
  labels:
    name: secure-namespace
```

## 6️⃣ Where It Should Be Applied (With Example)

Container network security should guide **ALL Kubernetes deployments**.

### **1. Applying Network Policies**

**Example: Configure Network Policies**

```bash
echo "=== Network Policies Configuration (Advanced) ==="

# 1. Create namespace
kubectl create namespace secure-namespace

# 2. Create network policy
kubectl apply -f - <<EOF
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-secure-ingress
  namespace: secure-namespace
spec:
  podSelector:
    matchLabels:
      app: secure-app
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: secure-app
    ports:
    - protocol: TCP
      port: 8080
EOF
```

### **Common Mistakes in Container Network Security**

❌ **Mistake 1**: No network policies
- Reality: No network policies (allow all)
- Fix: Implement network policies

❌ **Mistake 2**: No default-deny
- Reality: No default-deny (allow all)
- Fix: Implement default-deny

**Task 2: Identify Container Network Security Issue**

```bash
echo "=== Container Network Security Issue Identification (Advanced) ==="

echo "1. Checking for No Network Policies:"

  echo "   ALERT: No default-deny detected!"
  echo "   Investigation: Implement default-deny"

```

**Task 3: Remediate Container Network Security Issue**

```bash
echo "=== Container Network Security Remediation (Advanced) ==="

# 1. Implement network policies
echo "1. Implementing Network Policies..."
kubectl apply -f - <<EOF
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all-ingress
  namespace: secure-namespace
spec:
  podSelector: {}
  policyTypes:
  - Ingress
EOF

# 2. Implement network segmentation
echo ""
echo "2. Implementing Network Segmentation..."
kubectl apply -f - <<EOF
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-secure-ingress
  namespace: secure-namespace
spec:
  podSelector:
    matchLabels:
      app: secure-app
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: secure-app
    ports:
    - protocol: TCP
      port: 8080
EOF

# 3. Verify remediation
echo ""
echo "3. Verifying Remediation..."
kubectl get networkpolicies -n secure-namespace
kubectl describe networkpolicy default-deny-all-ingress -n secure-namespace

```
