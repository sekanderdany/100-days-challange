# 04.03 - Authorization (RBAC, ABAC)

## 1️⃣ What This Topic Is

Authorization (RBAC, ABAC) examines security measures for securing Kubernetes authorization mechanisms, understanding RBAC, ABAC, and secure authorization configurations.

**What this means:**
- Kubernetes authorization = verifying what you can do
- RBAC = Role-Based Access Control (roles, role bindings)
- ABAC = Attribute-Based Access Control (attributes, policies)
- Secure authorization configurations (least privilege, defense in depth)

**The Key Concepts:**

1. **Kubernetes Authorization Mechanisms**
   - RBAC (Role-Based Access Control)
   - ABAC (Attribute-Based Access Control)
   - Roles and RoleBindings
   - ClusterRoles and ClusterRoleBindings
   - Authorization monitoring (authorization events, authorization failures)

2. **Security Principles**
   - Defense in depth (RBAC, ABAC, monitoring)
   - Least privilege (authorization permissions)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (authorization logging)

**Why this matters:**
- Authorization is foundation of cluster security
- Authorization controls all access to cluster resources
- Authorization compromise = cluster-wide compromise
- Authorization handles all authorization decisions

## 2️⃣ What Problem It Solves

### Problem 1: Over-Privileged RBAC Policies

**Without secure authorization:**
- Over-privileged RBAC policies
- Attacker can escalate privileges
- Cluster compromise
- Data theft and service disruption

**With secure authorization:**
- Least privilege RBAC policies
- Privilege escalation prevented
- Cluster protected
- Data and services protected

### Problem 2: No Authorization Policies

**Without secure authorization:**
- No authorization policies
- Attacker can access any resource
- Cluster compromise
- Data theft and service disruption

**With secure authorization:**
- Authorization policies implemented (RBAC, ABAC)
- Resource access controlled
- Cluster protected
- Data and services protected

### Problem 3: No Authorization Monitoring

**Without secure authorization:**
- No authorization monitoring
- Authorization events undetected
- Authorization incidents undetected
- Incident response delayed
- Cluster compromise

**With secure authorization:**
- Authorization monitoring enabled
- Authorization events detected
- Authorization incidents detected
- Real-time detection
- Rapid incident response
- Cluster protected

### Real-World Impact

**Example: Tesla Kubernetes Breach (2018)**
- **Vulnerability**: Over-privileged RBAC policies
- **Root cause**: No RBAC least privilege
- **Authorization issue**: Attacker escalated to cluster-admin
- **Impact**: Attacker deployed miners across cluster
- **Lesson**: Implement RBAC least privilege

**Example: Uber Data Breach (2016)**
- **Vulnerability**: No authorization policies
- **Root cause**: No RBAC or ABAC implemented
- **Authorization issue**: Attacker accessed any resource
- **Impact**: 57 million customer records accessed
- **Lesson**: Implement authorization policies (RBAC, ABAC)

**Example: Capital One Breach (2019)**
- **Vulnerability**: No authorization monitoring
- **Root cause**: No authorization audit logging
- **Authorization issue**: Authorization events undetected
- **Impact**: 106 million customer records accessed
- **Lesson**: Implement authorization monitoring

## 4️⃣ How It Works (Conceptual)

### Kubernetes Authorization Mechanisms

**1. RBAC (Role-Based Access Control)**
- **Purpose**: Provide role-based authorization for Kubernetes API
- **Security Measures**: 
  - Roles (namespace-level, cluster-level)
  - Role bindings (associate roles with subjects)
  - Cluster roles (cluster-level)
  - Cluster role bindings (associate cluster roles with subjects)
  - Least privilege
- **Common Misconfigurations**: 
  - Over-privileged RBAC policies (cluster-admin everywhere)
  - No RBAC policies (all users have cluster-admin)
  - No RBAC least privilege (root access for all)
  - No RBAC separation (all resources in one role)
- **Example**: RBAC with roles and role bindings

**RBAC Types:**
- **Roles**: 
  - Namespace-level roles
  - Resource-level roles
  - Verb-level roles
  - Least privilege

- **Role Bindings**: 
  - Namespace-level role bindings
  - Associate roles with subjects (users, groups, service accounts)
  - Namespace-level RBAC

- **Cluster Roles**: 
  - Cluster-wide roles
  - Resource-level cluster roles
  - Verb-level cluster roles
  - Least privilege

- **Cluster Role Bindings**: 
  - Cluster-wide role bindings
  - Associate cluster roles with subjects (users, groups)
  - Cluster-level RBAC

**Best Practices:**
- Use namespace-level roles
- Use least privilege RBAC
- Use resource-level RBAC
- Use verb-level RBAC
- Regular RBAC audits

**Example**:
```yaml
# RBAC with roles and role bindings (secure, advanced)
apiVersion: v1
kind: Namespace
metadata:
  name: secure-namespace
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: developer-role
  namespace: secure-namespace
rules:
- apiGroups: [""]
  resources: ["pods", "services"]
  verbs: ["get", "list", "watch"]
- apiGroups: ["apps"]
  resources: ["deployments"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: developer-role-binding
  namespace: secure-namespace
subjects:
- kind: User
  name: "developer@example.com"
- kind: ServiceAccount
  name: "secure-service-account"
roleRef:
  kind: Role
  name: developer-role
  apiGroup: rbac.authorization.k8s.io
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: read-only-role
rules:
- apiGroups: [""]
  resources: ["nodes", "persistentvolumes"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: read-only-role-binding
subjects:
- kind: User
  name: "readonly@example.com"
roleRef:
  kind: ClusterRole
  name: read-only-role
  apiGroup: rbac.authorization.k8s.io
```

**2. ABAC (Attribute-Based Access Control)**
- **Purpose**: Provide attribute-based authorization for Kubernetes API
- **Security Measures**: 
  - ABAC policies (attributes, rules)
  - ABAC mode (authorization mode)
  - ABAC file configuration
  - ABAC monitoring
- **Common Misconfigurations**: 
  - Over-privileged ABAC policies (allow all)
  - No ABAC policies (deny all)
  - Weak ABAC policies (allow all users)
  - No ABAC monitoring
- **Example**: ABAC with policies

**ABAC Types:**
- **ABAC Policies**: 
  - ABAC policies (attributes, rules)
  - Resource-level ABAC policies
  - Verb-level ABAC policies
  - Attribute-based ABAC (user, group, namespace)
  - Least privilege

- **ABAC Mode**: 
  - ABAC mode (authorization mode)
  - ABAC file configuration
  - ABAC policy file
  - ABAC monitoring

- **ABAC Monitoring**: 
  - ABAC policy monitoring
  - ABAC authorization monitoring
  - ABAC audit logging
  - ABAC compliance reporting

**Best Practices:**
- Use ABAC policies (attributes, rules)
- Use least privilege ABAC
- Use resource-level ABAC
- Use verb-level ABAC
- Regular ABAC audits

**Example**:
```yaml
# ABAC with policies (secure, advanced)
# This would be configured via ABAC file configuration
# For example, using ABAC policy file (abac-policy.json):
[
  {
    "apiVersion": "abac.authorization.kubernetes.io/v1beta1",
    "kind": "Policy",
    "spec": {
      "user": "developer@example.com",
      "namespace": "secure-namespace",
      "resource": "pods",
      "readonly": true
    }
  },
  {
    "apiVersion": "abac.authorization.kubernetes.io/v1beta1",
    "kind": "Policy",
    "spec": {
      "group": "developers@example.com",
      "namespace": "secure-namespace",
      "resource": "pods",
      "readonly": false
    }
  }
]

# Example ABAC configuration file (kube-apiserver.yaml)
apiVersion: v1

metadata:
  name: abac-config
  namespace: kube-system
data:
  abac-policy.json: |
    [
      {
        "apiVersion": "abac.authorization.kubernetes.io/v1beta1",
        "kind": "Policy",
        "spec": {
          "user": "developer@example.com",
          "namespace": "secure-namespace",
          "resource": "pods",
          "readonly": true
        }
      },
      {
        "apiVersion": "abac.authorization.kubernetes.io/v1beta1",
        "kind": "Policy",

          "group": "developers@example.com",
```
