# 06.04 - Admission Controllers

## 1️⃣ What This Topic Is

Admission Controllers examines security measures for securing Kubernetes admission controllers, understanding validation, mutation, and secure admission configurations.

**What this means:**
- Kubernetes Admission Controllers = admission webhook controllers (Validating, Mutating)
- Admission Security = admission policies (OPA Gatekeeper, Kyverno, Ratify)
- Admission Compliance = admission compliance (SOC 2, PCI-DSS, HIPAA, GDPR)
- Secure admission configurations (policies, validation, monitoring)

**The Key Concepts:**

1. **Kubernetes Admission Security Areas**
   - Admission validation (image validation, policy validation, schema validation)
   - Admission mutation (pod mutation, label mutation, annotation mutation)
   - Admission policies (admission policies, admission rules, admission controls)
   - Admission monitoring (admission events, admission anomalies)

2. **Security Principles**
   - Defense in depth (validation, mutation, policies, monitoring)
   - Least privilege (admission access)
   - Zero-trust (never trust, always verify)
   - Default-deny (deny all, allow explicitly)
   - Audit everything (audit logging)

**Why this matters:**
- Admission controllers are critical for cluster security
- Admission controllers enforce security policies
- Admission controllers compromise = cluster-wide compromise
- Admission controllers handle all admission requests

**Example**:
```yaml
# Admission policies with Kyverno (secure, advanced)
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-non-root
spec:
  validationFailureAction: enforce
  background: true
  rules:
  - name: require-non-root
    match:
      resources:
        kinds:
        - Pod
    validate:
      message: "Root user is not allowed"
      pattern:
        spec:
          securityContext:
            runAsUser: 0
```

    - Pod

    - https://github.com/my-org/*

# 3. Verify admission validation
